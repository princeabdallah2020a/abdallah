## 3. Ranked bug list

**High**

- **B1 — Refused listings never recover (errors cached as idempotent results).** `central/.../includes/class-sync-api.php:113-150`: every response with code ≥ 400 is stored in `sync_events` and replayed for the same key (lines 125-130). The connector key is `uid|op|items.updated_at` (`dealer/.../connector/includes/class-sync.php:246`), and `retry_errors()` (`:364`) does not change `updated_at`. Repro: suspend the dealer, save a vehicle (402), reactivate, click "Retry refused vehicles" → same key → 402 replayed forever. Fix: don't store or replay errors, or add the attempt number to the key.
- **B2 — `PATCH /sync/vehicles/{id}/status` skips the plan-limit and active-dealer checks.** `class-sync-api.php:284-302` versus `PUT` at `:236` (`require_active`) and `:251-254` (limit). Repro: dealer on "start" (10 listings) at the limit; PUT a listing as `unpublished`, then PATCH `status=active` → 11 active; with a suspended dealer, PATCH → 200 and the listing is public. A signed connector key is enough, so the limit is a revenue bypass.

**Medium**

- **B3 — Two changes within the same second are lost.** `class-sync.php:246` (key derived from a second-granularity `updated_at`). Repro: in one second, reserve then re-publish a vehicle, with a sync after each → the marketplace stays `reserved`. Fix: key on a change counter or microsecond version.
- **B4 — Personal data retention/erasure gaps.**
  - `webhook_deliveries` (buyer name, phone and message) is never purged.
  - `Privacy::export/erase` (`central/.../class-privacy.php:48-100`) skip `wa_messages`, `call_logs` and `wa_conversations`.
  - The dealer `erase` (`dealer/.../automotive-dealer-crm/includes/class-privacy.php`, erase method) leaves `adc_lead_notes`.
  - The policy text promises 90 days for WhatsApp and calls.
- **B5 — Dealer site has no hardening headers.** The central site sends them (`class-api.php:41-48`); the dealer CRM and public site send none (no nosniff, no X-Frame-Options on `/manager/login/`, no Referrer-Policy). There is no CSP on HTML pages in either plugin.
- **B6 — Sales agent can unpublish.** `dealer/.../class-vehicles.php:~261-266`: the requested status `draft` is accepted from a role without `adc_publish_vehicles`. Repro: log in as a sales agent, edit a published vehicle, save with status draft.
- **B7 — Cancelling a sale auto-publishes a draft vehicle.** `class-sales.php:~148-150` sets `published` for any sold/reserved vehicle, including one that was a draft before the sale.

**Low**

- **B8 — AI preview ignores capabilities.** `connector/.../class-ai-endpoint.php:309` (`tool_update_vehicle_status`) previews for sales, rental and viewer roles, and the user is asked "reply OUI" before the confirm is refused. `update_vehicle_price` is correct.
- **B9 — The Arabic yes/no is missing.** `central/.../class-whatsapp-agent.php:154` only knows FR, Wolof and EN, against the 4-language promise.
- **B10 — Voice replay.** `class-telephony.php` `authenticate()` signs only `timestamp.body`, so a captured request replays for 5 minutes. The only holder of the secret is the gateway, so the practical risk is low.
- **B11 — Spec/doc gaps.**
  - The dealer side has no dark mode, no RTL and no `ar`/`wo` files (CLAUDE.md §2.1).
  - `docs/06-roadmap.md:56` says 13 CRM tables; the code creates 11.
  - The central "WhatsApp messages received" KPI also counts voice-call rows (`kind=call`).
- **B12 — Unverified notes, no test run.** The registration form may reveal that an email already exists (user enumeration), and the extend-subscription form accepts a very large number of months. Neither has an assertion in the suite.
